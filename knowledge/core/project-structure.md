# Project Structure

## Overview

A well-organized Unity project structure improves maintainability, collaboration, and build times. Unity projects follow specific conventions for folders, meta files, and assembly definitions that every developer should understand.

## Key Concepts

### Standard Folder Layout
- **Assets/Scripts/**: C# scripts organized by feature or layer
- **Assets/Prefabs/**: Reusable GameObject templates
- **Assets/Scenes/**: Scene files (.unity)
- **Assets/Art/**: Models, textures, materials, shaders
- **Assets/Audio/**: Music and sound effects
- **Assets/Resources/**: Runtime-loadable assets (use sparingly)
- **Assets/ScriptableObjects/**: Data assets and configs
- **Assets/Plugins/**: Third-party libraries and native plugins
- **Assets/Editor/**: Editor-only scripts and tools

### Meta Files
Unity generates `.meta` files for every asset. These contain GUIDs (Globally Unique Identifiers) that Unity uses internally to track references. **Never delete .meta files manually** — doing so breaks all references to that asset.

### Assembly Definitions
Assembly definitions (`.asmdef` files) split scripts into separate compiled assemblies. Benefits include:
- Faster compilation (only changed assemblies recompile)
- Better code organization and dependency management
- Clear boundaries between systems

## Code Examples

### Sample Assembly Definition JSON

```json
{
    "name": "Game.Core",
    "rootNamespace": "Game.Core",
    "references": [
        "Unity.InputSystem",
        "Unity.TextMeshPro"
    ],
    "includePlatforms": [],
    "excludePlatforms": [],
    "allowUnsafeCode": false,
    "overrideReferences": false,
    "precompiledReferences": [],
    "autoReferenced": true,
    "defineConstraints": [],
    "versionDefines": [],
    "noEngineReferences": false
}
```

### Assembly Definition Setup for a Project

```
Assets/
├── Scripts/
│   ├── Core/
│   │   ├── Core.asmdef          # Core game logic
│   │   ├── GameManager.cs
│   │   └── EventSystem/
│   ├── Player/
│   │   ├── Player.asmdef        # Player systems
│   │   ├── PlayerController.cs
│   │   └── PlayerStats.cs
│   ├── UI/
│   │   ├── UI.asmdef            # UI systems
│   │   ├── HUDController.cs
│   │   └── Menus/
│   └── Editor/
│       ├── Editor.asmdef        # Editor tools (Editor-only)
│       └── BuildScript.cs
```

## Best Practices

- **Feature-based organization**: Group by feature (Player/, Enemy/, UI/) rather than type (Scripts/, Prefabs/)
- **One asmdef per module**: Create assembly definitions for each major system
- **Never delete .meta files**: Always use Unity to rename/delete/move assets
- **Version control meta files**: Always include `.meta` files in git
- **Separate Editor code**: Put editor-only scripts in `Editor/` folders with Editor-only asmdefs
- **Avoid deep nesting**: Keep folder depth reasonable (3-4 levels max)
- **Consistent naming**: Use PascalCase for folders, clear descriptive names

## Common Mistakes

| Mistake | Problem | Solution |
|---------|---------|----------|
| Flat Scripts/ folder | Unmaintainable with 100+ scripts | Organize by feature/domain |
| Ignoring .meta in git | Broken references on other machines | Track all .meta files |
| Deleting .meta manually | GUID changes, references break | Use Unity to move/delete assets |
| Circular asmdef references | Compilation errors | Design clean dependency hierarchy |
| References in every asmdef | Bloated dependencies | Keep references minimal |
| Runtime code in Editor asmdef | Build errors | Use includePlatforms: ["Editor"] |
| Storing large assets in git | Repository bloat | Use Git LFS for textures/models |

## Recommended Structure Example

```
Assets/
├── _Project/                   # Your game content
│   ├── Scripts/
│   │   ├── Core/              # GameManager, events, utilities
│   │   ├── Player/            # Player controller, stats
│   │   ├── Enemies/           # Enemy AI, behaviors
│   │   ├── UI/                # HUD, menus
│   │   └── Data/              # SO definitions
│   ├── Prefabs/
│   │   ├── Player/
│   │   ├── Enemies/
│   │   ├── UI/
│   │   └── Environment/
│   ├── Scenes/
│   │   ├── Boot.unity
│   │   ├── MainMenu.unity
│   │   └── Gameplay.unity
│   ├── ScriptableObjects/
│   │   ├── Weapons/
│   │   └── LevelConfigs/
│   └── Art/                   # Or use Assets/Art/
├── Plugins/                   # Third-party assets
├── Editor/                    # Custom editor tools
└── Resources/                 # Runtime-loaded assets (sparse)
```
